# Module 2 - Day 4: Random Forest (Machine Condition Monitoring)

This directory contains a Random Forest classification example for predictive maintenance and machine condition monitoring.

## Overview

The project trains a Random Forest classifier on machine telemetry (temperature, vibration, pressure, RPM, current, operating hours) to predict machine status (`Normal`, `Warning`, `Critical`). It includes training, evaluation, prediction, alerting, and model packaging.

## Files

- `main.py` - End-to-end workflow: loads data, validates it, trains the model, evaluates performance, shows feature importance, makes a sample prediction, generates alerts, and saves the model package.
- `train_forest.py` - Data loading, validation, train/test split, model training, and model saving (joblib + metadata).
- `evaluate.py` - Model evaluation utilities and feature importance plotting.
- `predict.py` - Example code to build a single machine record and run a prediction.
- `alerts.py` - Simple alert generation and model save/load helpers.
- `maintenance_data.csv` - Sample dataset used for training and evaluation.
- `models/` - Directory where the trained model and metadata are stored (`random_forest.joblib`, `metadata.json`).
- `outputs/` - Output plots generated by the evaluation (feature importance plot).

## Requirements

- Python 3.x
- pandas
- scikit-learn
- matplotlib
- joblib

Install dependencies with:

```bash
pip install pandas scikit-learn matplotlib joblib
```

## Usage

Run the workflow from the module directory:

```bash
cd Module2/day4_random_forest
python main.py
```

To run without opening plot windows (headless servers / CI):

```bash
# PowerShell
$env:MPLBACKEND='Agg'; python main.py

# Bash
MPLBACKEND=Agg python main.py
```

Outputs:

- `models/random_forest.joblib` — saved model artifact
- `models/metadata.json` — model metadata including feature list and classes
- Console logs with training/evaluation metrics and prediction/alert messages
- `outputs/` — evaluation plot images (feature importance)

## Notes

- `train_forest.load_data()` resolves the CSV path relative to the module file so the scripts run correctly regardless of working directory.
- The example dataset is small and used for demonstration; real deployments require larger, balanced datasets and proper validation.
- Consider serializing pipelines (preprocessing + model) for production use.
